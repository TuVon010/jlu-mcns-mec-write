## 1. 方法框架与三种顺序

先依据当前稿件、公式和实际实现说明：整个方法包含什么、谁给谁输入、什么先算、哪些模块参与训练和在线执行。然后决定标题树；框架总述可放章导语，不要把整体与组成部分设成同层。整体及子模块名称保持稳定，但不要强制沿用旧 CORA、MADDPG 或某篇参考论文的结构。

区分三种顺序：

| 顺序 | 必须回答 | 写作检查 |
| --- | --- | --- |
| 推导顺序 | 固定哪些量，才能得到子问题或条件解？ | 提前推导可行，但明确条件和最优性范围 |
| 运行顺序 | 输入由谁在何时产生，结果交给谁？ | 伪代码、框图与实际调用一致，反馈要标清时隙或迭代 |
| 叙述顺序 | 读者需要先知道什么才能理解下一节？ | 可先总述后细节；与运行顺序不同时，显式说明调用关系 |

例如先推导资源分配闭式解、后介绍产生其输入的策略是可行写法；须说明“给定哪些决策求解”，以及这些决策运行时由哪个模块产生。不能让读者误以为策略同时输出了求解器负责的变量。若按运行顺序更清楚，则先策略、后条件优化器。**不要为了好写强行把独立分解、交替优化等方法套成 DRL 内部模块。**

可用的章法为“方法动机与总览 → 必要的形式化 → 各组件及依赖 → 训练/执行汇总 → 理论或复杂度”。并非每项都需要单独小节。问题分析解释困难来源，方法动机解释为何选择相应设计；集中写或分散在模块开头均可，避免重复。

**来源**：M1 00:50:38–01:06:17；M2 00:24:02–00:32:57。三种顺序是对讨论的提炼，不是会议原话或固定目录。

## 2. 模块数据流及历史案例

未读到当前算法描述或实现之前，不断定模块顺序。按实际存在的组件填写：

| 模块 | 输入及可得时间 | 输出及性质 | 发生时机 | 后续依赖 |
| --- | --- | --- | --- | --- |
| 前处理/关联/分区（如有） | 节点、任务及资源信息 | 观测特征、候选集合或派生决策 | 初始化/每时隙/每次迭代？ | 进入策略、约束或资源分配？ |
| 策略/主决策器 | 当前可获得的观测 | 建议动作或最终决策？ | 训练/在线？ | 是否还经过优化、投影或修复？ |
| 条件求解器（如有） | 已固定决策、资源预算 | 条件解及可行性状态 | 策略前/后或迭代中？ | 如何回填执行决策与成本？ |
| 执行及评价 | 最终实际决策 | 成本、奖励、下一状态 | 每次环境转移 | 是否与训练记录一致？ |

检查所有优化变量能否追溯到产生者；动作被修改后，成本、奖励、转移是否使用同一实际执行值。若求解器结果影响同一次策略输出，说明是迭代求解、前一时隙反馈还是未消除的循环依赖。不可行时的本地回退、丢弃、投影等只按真实实现记载，并解释重新计算的时延、资源和奖励。

多时间尺度方法还要写明各尺度的物理含义、更新频率、触发条件，以及慢尺度输出在快尺度内哪些保持固定、哪些重新计算。slot/epoch 名字不同不构成两时间尺度设计；检查每次更新所需信息是否已可得。（写作笔记幻灯片 10）

### 历史诊断示例：旧 CORA-MADDPG 讨论

M1 00:50:38–01:01:27 曾描述“聚类/分派目的地 → 学习卸载比例和轨迹 → 资源求解 → 执行与奖励”，并讨论不可行卸载回退。对话中的变量数量、模块位置和计算顺序尚有歧义；它只说明**需要查清数据流**，不证明当前方法仍有这些模块或顺序。不得据此断言当前系统包含控制 UAV、匈牙利算法或本地回退。方法已迭代时按 [版本与证据指南](11-version-and-evidence.md) 重新核实。

## 3. 序贯决策、动作分工与预处理

仅当实际方法使用序贯决策建模时采用本节。先说明 agent、信息条件、状态转移、时间尺度和目标，再按实际单/多智能体与可观测性选 MDP、POMDP、Markov game 或 POMG，不能因使用某算法就倒推出系统假设。

### 三类决策须区分

- `full system decisions`：原优化问题全部可控量。
- `learned actions`：策略实际输出的变量。
- `derived decisions`：给定状态和策略动作，经外部优化、匹配或修复得到的量。

若形式化先写完整联合决策，再缩减学习动作，解释映射 `a^{full}=F(s,a^{RL})`。若直接用 reduced action，则把外部求解器如何进入环境转移、奖励及可行性处理写清。两种均可；**不要求所有优化变量都由 actor 输出**。每类动作须列含义、范围、维度及变维处理，不能只说“only continuous decisions”。

### 物理状态、观测和网络输入须区分

`state` 表示所定义的系统状态，`observation` 表示 agent 真能取得的信息；网络输入还可能经过归一化、编码、补齐或掩码。记录物理量到输入的映射、单位/尺度、训练与测试是否一致，以及输出回到物理决策的映射。时间索引与归一化时间特征不可混称；不要把实现中的 `n/N` 原样放进状态式却不解释，也不要因它是“实现细节”而删掉影响复现的信息。

已在系统模型定义的任务/坐标不在这里反复重讲，只介绍它们怎样构成观测及新增变换。**来源**：动作分工提炼自 M1 00:57:41–01:00:34、M2 00:32:01–00:32:47；预处理核对由 M2 00:34:32–00:35:38 的时间与状态一致性讨论引出，是审查扩展。

## 4. 子方法与基础算法改造

每个子方法按“要解决的局部困难 → 输入/固定量 → 处理或数学目标 → 输出 → 后续调用”介绍；方法名不是作用解释。

- **分区/匹配（如有）**：说明优化的是距离、负载还是可达性，时间尺度及候选集合是什么；不能仅列 K-means、Hungarian 等名称。
- **资源分配（如有）**：明确负责 CPU、带宽等哪些量，固定哪些关联/卸载/轨迹变量，如何处理不可行解及回填总成本。
- **学习模块（如有）**：说明 agent、观测、实际动作、训练信息、所需损失/更新与在线部署；只介绍所用版本确有的机制，不把 replay、target network 或 CTDE 机械附加到每种算法。

### 改造已有算法时交代改动链

按下表准备材料，再写方法段落：

| 要素 | 需要的证据 |
| --- | --- |
| 基础组件与替换位置 | 原始论文/实现，本文替换 actor、表示、目标还是采样过程？ |
| 改造后接口 | 输入、输出、约束及与其他模块的连接 |
| 训练和推理变化 | 损失/估计量/更新/采样步骤的真实变化及前提 |
| 作用与代价 | 对应消融、运行成本或已证明性质；无结果时列待验证主张 |

## 5. Reward 与目标约束

若方法使用奖励，依次说明：原目标是什么 → 奖励与目标的方向及尺度关系 → 约束/失败怎样处理 → 最终执行值怎样参与评价。

- 负成本、归一化差值或增量奖励的定义必须明确；累计奖励与论文时域目标不一致时，解释折扣、终止或聚合差异，不能仅声称“等价”。
- 惩罚项写清违反条件、权重及范围，不能声称惩罚天然保证硬约束；约束若由投影、可行域或求解器保证，定位实际机制。
- 外部优化/修复后的实际动作应与成本、奖励和状态转移对应；区分“策略建议”与“实际执行”。
- `the weights` 必须指明符号或精确公式标签。优先级权重、成本归一化系数和失败惩罚不可混称。
- 不编罚项数量级、性能收益或理论保证。优先级机制的贡献与分组指标检查见 [11-version-and-evidence.md](11-version-and-evidence.md)。

长奖励定义按不同语义组件分段，短定义无需机械拆成多段。来源：M1 00:53:46–00:57:41、原批注 27/30；目标一致性检查是严谨性提炼。

## 6. 定理、证明与最优性范围

### 条件解不能扩大为整体最优

写闭式解或求解器最优性时，明确“在固定哪些变量、什么可行域及假设下，优化哪个子目标”。检查相应条件、推导和边界情况；KKT 条件、凸子问题的最优解、局部驻点和原联合问题全局最优不是同一主张。不能由资源子问题解得最优，直接写整个混合算法全局最优。若只返回数值近似解或发生回退，如实限定。

有分母、任务集合或关联条件时，重点核对零任务、空集合、零预算、未关联变量等实际可能的边界；逐项说明原问题约束在子问题中保留、消除、松弛或由其他模块处理，不能漏掉后仍宣称原问题可行。（Qi/Xing 的条件子问题章法见 [09](09-case-studies.md)）

### 证明应在正文中承担作用

Definition 命名对象，Assumption 声明前提，Lemma/Proposition/Theorem 承载有依据的结论，Corollary 应由已证结论推出，Conjecture 是未证猜想。按模板选择必要环境，不用 Definition 包装最优性断言，也不把猜想改名为 Proposition。（写作笔记幻灯片 11–12）

用期刊已有 theorem/proposition/proof 环境和自动编号。正文先说明结论用途并引用，证明内部按“假设/子问题 → 关键条件 → 推导或分情况 → 结论”组织，随后说明结果在算法何处使用。篇幅长可按模板放附录，但正文保留必要结论和引用。若删去命题不影响任何后续论证，检查是否只是装饰性陈述。

没有真实证明时不生成占位定理冒充完成结果；`MINLP`、`non-convex`、`NP-hard`、稳定训练曲线和理论收敛也不可互相替代。来源：M1 01:11:31–01:13:46、M2 00:22:30–00:25:05；最优性范围是对条件求解讨论的严谨性扩展。

## 7. 伪代码、复杂度和复核

- Inputs/Outputs 与问题变量一致，每个变量在使用前已产生；模块调用、迭代终止、不可行处理和返回值可追溯。
- 训练与在线执行分开说明；复杂度覆盖真实循环、网络、匹配、求解器与采样成本，不只统计 actor 前向计算。不编规模、硬件或复杂度结论。
- 框图箭头表示明确输入输出；学习反馈和执行数据流可区别标注，颜色不能代替文字解释。
- 算法的全称、简称、模块名在贡献、正文、伪代码及实验中一致。
- 改动方法后复核：形式化决策 → 学习动作/派生解 → 实际执行 → reward/目标 → 实验指标是否仍闭合。
