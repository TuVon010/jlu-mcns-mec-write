# 全文共性写作规范（优先级最高）

> 按任务范围使用。批注所指例子可提示全文同类问题，但应先在当前版本核实。版本与历史批注的判断见 [11-version-and-evidence.md](11-version-and-evidence.md)。先修正确性和逻辑，再修局部语言；纯润色不强制构建全套审查表。

## 1. 优先级与论证链

- **P0 结构/真实性**：研究主题两套不兼容口径；场景/层级/角色自相矛盾；模块依赖没有闭环；不同章节目标或变量不一致；数学目标、约束、奖励存在冲突；推导不成立；没有证据却宣称 NP-hard 或优越性。
- **P1 重要表达/严谨性**：Related Work 只罗列文献缺 gap；模型位置错误；公式没有引出或定义；仿真对比不能归因；多个创新点没有对应实验；缩写/标签/变量不统一。
- **P2 文字/样式**：标题大小写、连接词、个别语法、图字体、表格越界、冗余句子、LaTeX 排版。

主线是：

`研究背景与场景需求 → 已有方式及局限 → 系统架构与系统级挑战 → 文献 gap → 模型/假设 → 优化目标+变量+约束 → 求解难点 → 算法模块及数据流 → 定理/复杂度（如有） → 对比/消融/敏感性验证 → 结论`

检查每一条边能否回答“因此下一步为什么必须出现”。如果无法回答，插入合理过渡、改变顺序或删除不相关小节，**不要仅通过连接副词掩盖逻辑缺失**。

## 2. 一致性账本（修改前建立；修改后复核）

| 登记项 | 需记录的内容 | 检查范围 |
| --- | --- | --- |
| 场景定位 | *emergency communication* 还是 *post-disaster rescue*，其任务边界与部署时序；不是同义词 | 题名、摘要、引言、相关工作、系统图、结果图、结论 |
| 系统名 | 全称、唯一缩写、组成层、计算/控制/中继角色 | Abstract 单独首次定义；正文首次定义；全篇其余一致 |
| 问题名 | “优化什么”的描述性名称；需要时定义唯一简称，P1/P2 可用于问题编号 | 摘要、Contributions、P1/P2、算法、实验结论 |
| 算法名 | 全称、唯一缩写、algorithm vs method 的命名层级 | 摘要、Introduction、节标题、图题、伪代码、结论 |
| 决策变量 | 名称、符号、定义域、离散/连续、索引/时隙、来源和计算者 | Problem、POMG/POMDP、actor 输出、外部求解器、实验 |
| 术语与动词 | delay vs latency、task execution vs computation、UD vs user | 全文一词一义；确需区分时明确定义 |
| 数学记号 | 集合/向量/矩阵、上下标、单位与时间索引 | 公式、图注、符号表、证明、伪代码 |
| 创新—证据 | 每项贡献对应具体内容及适当的推导、比较或实验；机制级主张需要相应粒度的证据 | Introduction ↔ 模型/算法 ↔ Simulation |

### 缩写

- 摘要与正文**各自独立**做首次“全称 (缩写)”定义，其后优先缩写；专业名词常用正式写法，例如 *uncrewed aerial vehicle (UAV)*（若投稿领域和参考文献确有偏好，以期刊要求为准）。
- 首次定义后不在全文反复以全称/缩写交替出现；只出现一次或不常用的术语不强制造缩写。
- `low Earth orbit (LEO) satellite`：LEO 是轨道类别，不能把单独“LEO”直接当作“卫星”使用。
- `OP problem`、`MEC computing` 等“缩写已含名词再重复”的写法要审查。

### 决策变量次序

示例（仅示意，不是要求所有论文采用此顺序）：

`task offloading → computing resource allocation → UAV trajectory planning`

在 Abstract、Contributions、Problem Formulation 与 Algorithm 描述中，**清单罗列顺序**尽量一致。若实际执行是“先轨迹→资源”，要单独写清“列举顺序”与“计算依赖顺序”不同，不能为了修文风而改变算法真实执行步骤。

### 命名层级

- 研究贡献的小标题遵循目标期刊/组内排版，如 `\textbf{System Architecture.}`、`\textbf{Problem Formulation.}`、`\textbf{Algorithm Design.}`、`\textbf{Performance Evaluation.}`。Title Case、加粗只用于并列标题，不要求每个正文单词首字母大写。
- **整体**叫 proposed `XXX algorithm` 时全篇保持；其**内含**可称 `mechanism`、`method`、`module`、`scheme`，但必须让读者知道并列关系和包含关系。`approach` 在组内材料中有更宽泛的用法，存在明确期刊风格时可使用，勿教条。
- 标题结构保持平行：`UAV-Assisted ...`、`Satellite-Assisted ...` 比一个介词短语一个单名词好；变量清单的语法结构保持平行（task offloading, UAV trajectory planning, and computing resource allocation）。

## 3. 大小逻辑均遵循总—分—合

### 定义一次，后续补充新增信息

用简短账本记录关键对象的首次定义和后续用途：Overview 解释节点组成与职责，Basic Model 给数学定义，Algorithm 说明如何使用，Simulation 交代取值与统计。后文引用已有定义，避免重复讲任务大小、位置或移动规律。公式前说对象与必要性，公式后释符号和条件；不在两侧重复同一句话。简洁不能删除复现需要的单位、假设或变换。（M2 00:10:21–00:16:07、00:35:38）

### 章节级

- 章节第一段通常说“本章依次做什么/聚焦哪三个方面”；如章节极短可按论文模板处理。
- 同层标题具有同层抽象级别：`Communication Model` 与 `Computation Model` 是并列；`SUAV Energy Consumption Model` 更像其中一部分或更细级别，除非另有理由。
- 每节的末段把此前内容归纳到 gap、问题性质或后续章节，不仅是列举完停止。

### 段落级

常用次序：**主题句（这一段在讲什么）→ 展开/举例（可含 2–4 个代表工作）→ 局限/结果/转折（为什么引下一段）**。篇幅大体平衡，是信息完整性的提示，**不能为了凑等长加入无关文本**。

连接词必须表达真实关系：

| 关系 | 常用措辞 | 使用限制 |
| --- | --- | --- |
| 具体化 | Specifically, In particular | 总述之后细化，不表示完全并列 |
| 同方面并列 | Moreover, Furthermore, Additionally | 同一逻辑主轴延续；换到新主题不要机械 `Moreover` |
| 原因 | Because, Due to, Given that | 避免因果倒置 |
| 转折 | However, Nevertheless, By contrast | 对比对象须可识别，不要当万能开头 |
| 推论 | Therefore, Consequently, Accordingly | 结论须有上文支撑 |
| 转向下一主题 | To address these limitations, Beyond ..., Another research direction ... | 用于换主题/新段时更清楚 |

“先写总述、再用 Specifically 分层解释”对应师姐批注 12–13、录音对 System Overview 的强调；“Moreover 不宜作为新大方向开头”对应批注 7。

## 4. 公式与技术叙事

把公式视为论证句的一部分：

1. 先说**研究对象、关系和必要性**，如 `The slot-level propulsion energy of UAV u is given by ...`。
2. 再给公式，末尾按语法加标点。
3. 随后介绍核心变量、单位、适用条件和引用来源；常识项可简写，不必展开所有次要恒等式。
4. 后续结果引用明确公式标签：`According to (\ref{...})` 或 `using \eqref{...}`，而非 `the above`。
5. 多条同类约束使用同一子公式组 `(Pa)–(Ph)`，逐条解释其含义；不同目的的物理模型不要仅为节省版面而堆成一块。
6. 推导给出中间逻辑；closed-form 结果说明从何种问题/条件/定理得到，避免“突然给出答案”。

数学真实性特别注意：

- **MINLP 不蕴含 NP-hard 的自动证明**；若主张 NP-hard，应提供严谨归约/复杂性论证或适用的充分依据。
- 无法从论文提供的模型推导的闭式结果、收敛性或可行性保证不能凭写作模板生成。
- 优化问题中的能耗/时延物理约束不因奖励函数加入惩罚项就自动成立；要核对优化域、环境执行或投影/修复机制。
- 对优先级权重的来源与约束引用精确到 `\eqref{...}`；任务优先级和抢险严重程度之间的映射需有明确定义与合理性。

## 5. 英文与 LaTeX 规范

- **正文一般现在时**描述本文系统和一般规律；**相关工作过去时**描述已开展研究，必要时可使用现在完成时描述研究趋势；**结论**可用现在时总结事实、现在完成时描述本文已完成工作。文法应服从句义，不能机械全篇替换。
- 引入首次术语之后使用缩写；名词、冠词、单复数、量纲、代词先行词必须准确。
- 相同的两个动词如 `denotes`、`represents`、`indicates` 可以适当交替，但不能以“多样性”为由替换成含义不同的词。
- `e.g.` 是举例；`i.e.` 是等价解释；减少过长插入语、连续多重 `and`、难以定位的 `which`、非必要分号。
- 引文精确归属，不堆同一实验室文献，不只追新也要引用最关键原始研究；优先近年的高质量 IEEE Trans/顶会，但“近三五年”“全文四五十篇”是经验值不是硬指标。
- LaTeX 草稿保持可读：一段一空行、每个公式环境独立、标签语义化、缩进/换行规整；不把所有公式挤在同一行。
- 字体、三线表、图例、caption、图题字体与尺寸遵从最终投稿模板；避免行溢出和表格出栏。

## 6. 每次审查的流程

全文或方法审查可构造下列三张表；局部修改只维护受影响的条目：

**（A）研究主线对照**：研究挑战 `C1..Cn` ↔ 对应架构/优化/算法 `M1..Mn` ↔ 验证图/实验 `E1..En`。若某项无法映射标记“证据缺口”。

**（B）术语/数学一致性**：缩写、目标、决策、符号、时间尺度、索引、算法全称。特别检查局部成本 vs 全局成本、任务时延 vs 通信时延、用户能耗 vs UAV 能耗。

**（C）算法依赖**：模块名、输入、输出、是否学习得到、是否优化器计算、是否作用奖励/约束、是否训练时与执行时都需要。

然后依照 P0→P1→P2 给优先级，统一推送到全文（而不是只修批注所指句子），最后做术语和引用回归。
